Reasoning Pricer

A Python token valuation analysis tool that generates comprehensive markdown reports for Solana tokens using a AI Acceleration reasoning model with AI acceleration dynamics.

Overview

This project analyzes token data and generates detailed valuation reports based on a novel pricing framework that models token value under extreme economic scenarios, incorporating AI acceleration impact on asset valuations.

Two engines, two sets of constants. reasoning_pricer/pricing_engine.py produces the per-token reports in reports/tokens/ and the risk-class summaries. reasoning_pricer/tariff_generator.py is a deliberately separate model — its own token types, base ranges, risk classes, and AI factors — and it produces reports/predicted_price.md and reports/tariff_rate.md. The tables in this README document pricing_engine. For the tariff_generator constants, see blog/02-pricing.md. The same token will get different multipliers from the two engines; that is expected, not a bug.

The AI Timeline

The key insight is that AI progress affects different asset types differently: - Static assets (BTC, gold, fiat-pegged) decline in relative value as AI accelerates - AI-evolving assets (utility tokens, AI-native protocols) appreciate as AI enables rapid evolution

Timeline Phases

Phase Timeframe AI Capability Impact
Pre-AI Baseline 2024 Baseline Reference point for all ratios
Personal Architect 2025 Q2 Scientific agents First divergence between tracks
Global Acceleration Accord 2025 Q4 AI acceleration frameworks Acceleration impacts, protocol utility rises
Creative Renaissance 2026 AI as creative partner Peak AI acceleration — the phase the current reports price against
Agentic (Waifu Aligner) 2027 Autonomous AI agents Full AI ecosystem integration

The phase is selected by ReasoningPricer.get_current_ai_phase(), which is pinned to August 2026 (Q3) rather than read from the system clock. This keeps report output reproducible — regenerating against archived data yields the numbers it was originally published with.

The month is cosmetic: the 2026 phase is annual, so any month of 2026 resolves to Creative Renaissance. The pinned year is the one that matters. It will keep returning Creative Renaissance into 2027 instead of advancing to Agentic (static assets 5.0x → 2.0x, AI-native 25.0x → 50.0x), so bump it deliberately when you want to publish the next phase's numbers.

Fiat-pegged and meme tokens are not AI categories; they are token types, and their collapse comes from their base multiplier range, not the timeline factor.

Valuation Model

Core Formula

Real Multiplier = Base_Type_Multiplier × AI_Timeline_Factor × Risk_Class_Adjustment × Insider_Risk_Factor × Capital_Flight_Factor × Liquidity_Risk_Factor

Components

  • Base Type Multiplier: Midpoint of the token type's range (e.g., 35x for Hard Money)
  • AI Timeline Factor: Multiplier based on AI acceleration phase and token's AI category
  • Risk Class Adjustment: 0.6x - 1.2x based on token's risk classification (A 1.2 / B 1.0 / C 0.8 / D 0.6)
  • Insider Risk Factor: 0.5x - 1.0x, computed as 1.0 - (insider_score / 100) × 0.5
  • Capital Flight Factor: 0.2x - 1.2x based on token rank
  • Liquidity Risk Factor: 0.90x - 1.0x based on market cap; SOL is exempt at 1.0x

Note that tariff_generator multiplies in one additional term that pricing_engine does not: the analyst tariff_override as 1 + (tariff_override / 100).

Tariff Calculation

The tariff represents trading friction, derived from the real valuation multiplier:

tariff = max(0, (100 / real_multiplier) - 10)

Worked against the August 2026 data snapshot, pricing_engine gives:

Token Real Multiplier Tariff
USDT 0.0119x 8,408%
WBTC 9.07x 1%
SOL 28.73x 0%
RENDER 58.46x 0%

reports/tariff_rate.md and reports/predicted_price.md show different figures for the same tokens because they come from tariff_generator — see the note at the top of this README.

Exchange Multiplier

exchange_multiplier = 1.0 + (tariff_override / 100.0)

This is derived from the analyst-set tariff_override field in the data file, not from the computed tariff above. In pricing_engine it is a reporting field only. In tariff_generator it is also a factor in the real multiplier.

Usage

Prerequisites

  • Python 3.10 or later

Run

bash python -m reasoning_pricer.main

After refreshing data/, regenerate the blog's master table too — it is built from the same snapshot and will otherwise go stale:

bash python scripts/build_blog_master_table.py

Input Data Format

Token data files in data/ should be JSON arrays with the following structure:

json [ { "symbol": "SOL", "name": "Solana", "archetype": "Class B (Systemic)", "insider_score": 48, "rank": 5, "token_type": "ProtocolUtility", "ai_category": "PassiveUtility", "tags": ["native", "gas", "layer-1"], "tariff_override": 30, "reason": "The Currency of the Realm." } ]

Token Fields

Field Type Required Description
symbol string Yes Token ticker symbol
name string Yes Full token name
archetype string Yes Risk class (e.g., "Class A (Real Yield)")
insider_score number Yes 0-100 insider concentration (higher = more centralized)
tariff_override number Yes Manual tariff friction percentage
reason string Yes Analyst notes
market_cap number Yes Tokens without a positive market cap are filtered out
price number Yes Tokens without a positive price are filtered out
tags array No Array of tags for auto-detection (defaults to empty)
fdv number No Fully diluted valuation
rank number No Market cap rank (1-999) for capital flight calculation
token_type string No Explicit type override (see below)
ai_category string No Explicit AI category override (see below)
parent_token string No Parent token for wrapped/bridged assets

There is no AINative or AIEnabled token type in pricing_engine — AI exposure is expressed through the AI category, not the token type. tariff_generator does define both (AINative 15x - 40x, AIEnabled 10x - 30x) and uses a different set of ranges throughout; see blog/02-pricing.md.

AI Categories

Value Timeline Factor (2026) Description
Static 0.20x Cannot evolve (BTC, gold)
PassiveUtility 1.80x Limited AI adaptation
AIEnabled 4.44x Can integrate AI (DePIN)
AINative 8.33x Built for AI ecosystems
AIEvolving 10.42x Self-modifying with AI

Each is phase_multiplier / category_baseline. AIEnabled interpolates between the protocol-utility and AI-native tracks using a per-year progress weight (0.6 in 2026); AIEvolving takes a 25% premium over the AI-native track.

Rank-Based Capital Flight Factor

pricing_engine uses three bands:

Rank Range Factor Description
1-9 1.2x Blue-chip premium
10-99 0.8x Mid-tier drag
100+ 0.2x Heavy penalty for illiquid alts

A token with no rank defaults to 9999, landing in the 0.2x band.

tariff_generator uses five bands instead (1.2x / 1.0x / 0.8x / 0.5x / 0.2x at rank 10 / 50 / 100 / 300), and defaults a missing rank to 500.

Tag-Based Auto-Detection

If token_type is not explicitly set, it's auto-detected from tags:

Checked in this order; first match wins:

Tag Pattern Detected Type
gold, commodity CommodityBacked
fiat, stable FiatPegged
hard-money, pow HardMoney, or WrappedBridge if parent_token is set
liquid-staking, or any tag containing staked LiquidStaking
meme, pepe, dog Meme
rwa, yield, treasury-yield RealYield
(no match) From archetype: A/B → ProtocolUtility, C → Governance, D → Meme

If ai_category is not explicitly set, it's auto-detected from tags:

Tag Pattern AI Category
ai, agent, autonomous, agi, aligner, fetch, ocean, … AINative
compute, gpu, render, akash, cloud, parallel, … AIEnabled
hard-money, pow, bitcoin, gold, btc, commodity Static
(default) PassiveUtility

Tags are split on - and . and matched as whole words, so ai-inference and ai-data match the ai keyword while cross-chain and airdrop do not. This detection is only a fallback — an explicit ai_category in the data file always wins.

Output

Generated reports are saved to the reports/ directory: - reports/index.md - Main index with all tokens - reports/predicted_price.md - AI-acceleration predicted price report (tariff_generator) - reports/tariff_rate.md - Price / exchange price / tariff table (tariff_generator) - reports/tokens/{symbol}.md - Individual token analysis (pricing_engine) - reports/summaries/{class}.md - Risk class summary (pricing_engine)

Classification Notes

Two bugs in pricing_engine's data path were fixed in August 2026. They had affected reports/tokens/ and reports/summaries/ only — predicted_price.md and tariff_rate.md come from tariff_generator, which always parsed these fields correctly.

  1. data_loader.py silently dropped every explicit token_type and ai_category. Its lookup tables were keyed in snake_case ("hard_money", "static") while the data files are written in PascalCase ("HardMoney", "Static") — the two key sets had zero overlap, so every explicit classification fell through to tag detection. Lookups are now normalised, and both spellings work.

  2. AI category tag detection matched substrings, not whole tags. The keyword "ai" matched inside multi-chain, cross-chain, vc-chain, airdrop, and failed-peg, so PYTH, DRIFT, KMNO, 1INCH, MEW, and UXD were all classified AI-Native. Tags are now split on - and . and matched as whole words, so ai-inference still matches ai but cross-chain does not.

The two compounded: because (1) discarded the explicit ai_category, (2) got to decide every token's AI category. Fixing both moved 31 of 110 tokens — RENDER 110x → 58x, AI16Z 23x → 1.1x, HNT 22x → 54x.
